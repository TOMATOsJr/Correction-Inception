# Correction Inception

Improvises the transcript given by the vision model within an automated answer sheet evaluation pipeline using multi agent vlm (adverserial and advocate agents) architecture.

**Team Dropouts**: Prabhav (2023115008), Jayant (2023115016), Saloni (2023115001), Sampath (2023102033). LMA Group Project 2026.

AI grading of handwritten answers runs in two stages: a vision-language model transcribes the page, then an LLM grades the text.
Reading mistakes cause wrong grades in two directions:
* **misreads** cost students marks they earned;
* **silent corrections** ("correction inception") are where the reader quietly fixes a student's mistake, so they receive marks they didn't earn.

We detect and repair transcription errors that matter for grading **without relying on a better OCR**.
Two opposing agents (an Advocate and an Auditor) propose fixes. Every fix must be verified by evidence: a context-free
re-read by a fine-tuned verbatim reader, and consistency with the student's own later work (never correctness).
Anything that can't be verified is escalated to a human. See `docs/proposal/`.

## Repository layout
```
src/eval/        evaluation pipeline (re-creates the EDU-CIRCUIT-HW method for any transcriber)
  run_ocr.py               transcribe pages with any model (Gemini / OpenAI-compatible / local Qwen + LoRA)
  evaluate_recognition.py  judge -> filter -> SER/AEC -> error taxonomy (paper's steps 9-12)
  llm.py, edu_compat.py    model backends, caching, loading the paper's prompts unchanged
  grade_impact.py          transcription-caused grading errors (TCE), our implementation (paper's code unreleased)
  calibrate_judge.py       calibrate a replacement judge against the paper's shipped judge verdicts
src/finetune/    faithful reader: FERMAT splits + silent-correction metric, QLoRA training, FERMAT eval  [ready, run on Kaggle]
src/agents/      core.py (claims, tools, rule-based arbiter) + agents.py (Advocate/Auditor)  [offline-tested]
src/analysis/    no-API analyses on shipped data (grading vs reading errors, arithmetic consistency, redundancy)
notebooks/       Kaggle notebooks: 01 reader baselines, 02 fine-tuning (generated by scripts/make_notebooks.py)
data/            dataset instructions (data itself not committed)
external/        EDU-CIRCUIT-HW code + data (cloned by scripts/setup.ps1, not committed)
results/         metrics.json and summaries for every run
docs/            proposal, setup guide, mid-submission report
```

## Quick start
```powershell
.\scripts\setup.ps1                                   # clone the paper repo, install, self-test
# add GEMINI_API_KEY to .env, then unzip the EDU-CIRCUIT-HW data into external\CIRCUIT_EDU_HW_ACL
python src\eval\evaluate_recognition.py --reference   # baseline numbers from the paper's released outputs (no API)
python src\eval\run_ocr.py --split debug --task repro_debug --model gemini-2.5-pro
python src\eval\evaluate_recognition.py --task repro_debug --model-dir gemini-2.5-pro
```

## Baseline results so far
Recomputed from the paper's released judge outputs (513 observation samples, judge = Gemini 2.5 Pro):

| Transcriber | Sample Error Rate | Student-bootstrap 95% CI | Avg errors / sample |
|---|---|---|---|
| Gemini 3 Pro | 37.6% | 31.7–42.9 | 0.62 |
| **Gemini 2.5 Pro (paper baseline)** | **53.4%** | 48.0–59.9 | **1.23** |
| Qwen3-VL-Plus | 61.8% | 53.5–69.7 | 1.38 |
| GPT-5.1 | 71.5% | 62.8–79.5 | 2.05 |
| Claude Sonnet 4.5 | 80.7% | 74.4–87.1 | 2.77 |
| Qwen3-VL-8B (thinking) | 85.6% | 79.7–91.5 | 2.81 |

Full output: `results/baseline_reference/reference_paper_metrics.json`.
